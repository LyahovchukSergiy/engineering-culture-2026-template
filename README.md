# Стартовий сервіс курсу

Шаблон репозиторію курсу «Інженерна культура та інструменти командної
розробки», Острозька академія, 2026.

Усередині невеликий веб-сервіс на FastAPI: список записів, створення запису,
читання одного запису і перевірка живості. Домен навмисно нейтральний, бо на
ЛР1 ви обираєте свою тему і під неї переписуєте цей README, а не код. Запис
однаково працює і як бронювання аудиторії, і як заявка в helpdesk, і як
знахідка в бюро знахідок.

Цей README ви переписуєте на ЛР1 під свій продукт. Перед тим прочитайте його
до кінця: розділ про навмисно недороблене пояснює, чому половина файлів тут
виглядає незакінченою.

## Запуск

Два шляхи. Перший ні від чого не залежить, другий швидший, якщо у вас уже все
стоїть.

### У браузері, нічого не встановлюючи

На сторінці свого репозиторію натисніть зелену кнопку «Code», вкладку
«Codespaces», «Create codespace on main». За пару хвилин відкриється готовий
VS Code з потрібним Python, `make` і вже поставленими залежностями.

Це найкоротший шлях для Windows і для будь-якої машини, де щось не ставиться.
Безкоштовного тарифу GitHub вистачає з запасом, а GitHub Student Developer Pack
дає ще більше.

### Локально

Потрібен Python 3.12 або новіший і `make`. Docker знадобиться з ЛР6.

```bash
git clone <адреса вашого репозиторію>
cd <папка>
make run
```

Перший запуск сам створить `.venv` і поставить залежності, тому займе хвилину.
Далі сервіс живе на http://127.0.0.1:8000, документація API на
http://127.0.0.1:8000/docs. Хост і порт беруться зі змінних оточення, тому
якщо порт 8000 зайнятий, задайте `APP_PORT` у своєму `.env`.

`make run` тримає термінал зайнятим, поки сервіс працює, і перезапускає сервіс
сам, коли ви правите код. Перевіряти його відкривайте друге вікно:

```bash
curl http://127.0.0.1:8000/health
```

## Тести і лінтер

```bash
make test
make lint
```

Обидві команди мають бути зеленими на свіжому клоні. Якщо ні, це не ваша
провина і не нормальний стан, напишіть в issue курсу.

## Контракт Makefile

Чотири цілі з фіксованими іменами. Валідатор курсу перевіряє саме імена, а не
те, що за ними стоїть, тому змінити стек ви можете, а перейменувати цілі ні.

```
make lint    статичні перевірки коду
make test    тести
make run     підняти сервіс локально
make build   зібрати образ
```

Ще є `make install` і `make clean`, вони допоміжні.

## Карта репозиторію

```
.devcontainer/      готове оточення для GitHub Codespaces
src/app/            код сервісу
  main.py           ендпойнти
  models.py         моделі даних
  storage.py        сховище в пам'яті
  config.py         читання змінних оточення
tests/              тести сервісу
tests/legacy/       тести курсу до legacy/pricing.py, не змінюються
legacy/pricing.py   успадкований модуль, який ви рефакторите на ЛР3
backlog.md          вісім фіч з критеріями приймання
CONTRIBUTING.md     ваша робоча угода з собою, заповнюється на ЛР1
Dockerfile          заготовка, добудовується на ЛР6
.github/workflows/  заготовка пайплайна
.env.example        перелік змінних оточення
```

Далі репозиторій обростає файлами сам: `CHANGELOG.md` з ЛР6, `SECURITY.md`
з ЛР7, `docs/adr/` з ЛР3, `docs/postmortems/` з ЛР10, `AGENTS.md` з ЛР11.
Папок на кшталт «ЛР4» тут не буде: артефакт лежить там, де він лежав би в
робочому проєкті.

## Конфігурація

Скопіюйте `.env.example` у `.env` і заповніть під себе. Порожнє значення
означає «взяти те, що зашите в `app/config.py`».

`.env` у git не потрапляє і потрапити не повинен. Секрети живуть у GitHub
Secrets, і з ЛР7 це перевіряється окремо.

## Що тут навмисно недороблено

Шаблон не є взірцевим проєктом. Кілька речей у ньому зроблені так, як їх
роблять в реальності на старті, і доводити їх до ладу ви будете самі:

`Dockerfile` не збирається. У ньому позначки TODO і рядок, який валить
складання. Поки ви його не добудуєте на ЛР6, `make build` падає, і це очікувана
поведінка, а не поламаний шаблон.

Пайплайн робить тільки лінтер і тести. Складання образу, required checks і
бейдж статусу з'являються на ЛР4.

Замість логів у коді стоїть `print`. Структуровані логи з рівнями і
`request_id` це ЛР9.

Валідація вводу мінімальна, перевірки доступу немає взагалі. Одну реальну
знахідку у власному коді ви шукаєте на ЛР7.

`legacy/pricing.py` написаний погано, і це теж зроблено свідомо: дублювання,
числа без назв, три рівні вкладеності. Тести до нього фіксують поточну
поведінку, тому після вашого рефакторингу на ЛР3 вони мають лишитись зеленими
без жодної правки.

## Правило про дані

Репозиторій публічний весь семестр. Реальних даних академії, справжніх
прізвищ, контактів, номерів наказів і внутрішніх документів у ньому бути не
може. Усі дані, які ви заводите, генеровані або вигадані.

Це не формальність: публічність потрібна, щоб безкоштовно працювали Actions,
Pages і GHCR, і ціна за неї саме така.
