# Беклог продукту

Вісім фіч, з яких ви берете роботу протягом семестру. Жодна з них не вигадана
під конкретну тему: усі вісім однаково лягають на бронювання аудиторій,
helpdesk, афішу подій, трекер витрат, бюро знахідок і чергу на консультацію.
Змінюється тільки те, як ви називаєте записи.

Формат тут не для краси. Критерії приймання це те, за чим ви на ЛР1 заводите
issue і за чим потім самі себе перевіряєте: поки жоден пункт не поставлений,
задача не зроблена. Копіюйте цю структуру в issue дослівно, включно з
чекбоксами.

Порядок у списку це не пріоритет. Що брати першим, вирішуєте ви.

---

## 1. Фільтр списку за статусом

`GET /items` віддає геть усе. Коли записів більше двадцяти, з таким списком уже
незручно працювати.

Критерії приймання:

- [ ] `GET /items?status=done` віддає лише записи з цим статусом
- [ ] невідоме значення статусу дає 422 з поясненням, а не порожній список
- [ ] без параметра відповідь не змінюється
- [ ] є тест на кожен з цих трьох випадків

Поза межами: сортування і пагінація, це окремі фічі.

## 2. Пошук за текстом

Знайти запис за назвою зараз можна тільки очима.

Критерії приймання:

- [ ] `GET /items?q=текст` шукає підрядок у полі `title` без урахування регістру
- [ ] пошук працює разом з фільтром за статусом
- [ ] порожній `q` не ламає відповідь
- [ ] є тест на збіг у різних регістрах

Поза межами: пошук по опису, морфологія, ранжування.

## 3. Пагінація списку

Зараз список віддається одним шматком. На тисячі записів це помітно і по
пам'яті, і по часу відповіді.

Критерії приймання:

- [ ] `GET /items?limit=&offset=` працює, `limit` за замовчуванням 20
- [ ] `limit` більший за 100 обрізається до 100
- [ ] у відповіді є загальна кількість записів
- [ ] від'ємні значення дають 422

Поза межами: курсорна пагінація.

## 4. Оновлення запису

Статус запису зараз проставляється один раз при створенні і назавжди.

Критерії приймання:

- [ ] `PATCH /items/{id}` міняє `title`, `description` або `status`
- [ ] передані поля міняються, не передані лишаються як були
- [ ] неіснуючий `id` дає 404
- [ ] є тест на часткове оновлення

Поза межами: історія змін запису.

## 5. Видалення запису

Запис, створений помилково, лишається в списку назавжди. Прибрати його
зараз нічим.

Критерії приймання:

- [ ] `DELETE /items/{id}` віддає 204 і прибирає запис зі списку
- [ ] повторне видалення того самого `id` дає 404
- [ ] є тест на обидва випадки

Поза межами: кошик і відновлення видаленого.

## 6. Зрозумілі повідомлення про помилки

Зараз при кривому вводі клієнт отримує технічний дамп від валідатора. Прочитати
його може той, хто писав сервіс.

Критерії приймання:

- [ ] помилки валідації приходять у єдиному форматі з полем і причиною
- [ ] текст написаний для того, хто робить запит, а не для розробника
- [ ] формат описаний у README
- [ ] є тест, який перевіряє форму відповіді, а не текст слово в слово

Поза межами: локалізація на кілька мов.

## 7. Сортування за датою

Порядок записів у списку зараз збігається з порядком створення випадково, а не
за домовленістю.

Критерії приймання:

- [ ] `GET /items?sort=created_at` і `sort=-created_at` дають зворотні порядки
- [ ] невідоме поле сортування дає 422
- [ ] сортування працює разом з фільтром і пагінацією
- [ ] є тест на обидва напрями

Поза межами: сортування за довільним полем.

## 8. Експорт списку у CSV

Забрати дані назовні можна тільки копіюванням JSON руками.

Критерії приймання:

- [ ] `GET /items/export` віддає CSV з заголовком і правильним `Content-Type`
- [ ] експорт враховує фільтр за статусом
- [ ] кома і лапки всередині тексту не ламають файл
- [ ] є тест на запис з комою в назві

Поза межами: експорт у Excel і вивантаження за розкладом.
